# Оптимизированные обложки упражнений — дизайн

## Цель

Обложки упражнений должны появляться быстро в большой библиотеке, не создавая
отдельный API-запрос для каждой карточки и не передавая многомегабайтные
исходные изображения. Требование относится к новым обложкам; существующие
ссылочные и ранее загруженные обложки остаются совместимыми.

## Границы и критерии приёмки

- Новая обложка хранится и показывается только как приватный оптимизированный
  WebP-вариант 16:9 размером 320×180 px.
- Целевой максимальный размер результата — 100 KiB. Качество WebP подбирается
  понижающими шагами, чтобы уложиться в этот предел; файл, который нельзя
  корректно преобразовать, получает понятную ошибку.
- Тренер может загрузить JPEG, PNG или WebP и может взять кадр из видео. Оба
  пути создают один и тот же канонический вариант.
- Сохранение упражнения с новой обложкой заблокировано, пока сервер не
  подтвердил канонический вариант. Ошибка обработки не привязывает исходник к
  упражнению и позволяет выбрать файл повторно.
- Библиотека тренера получает URL всех нужных обложек одним авторизованным
  запросом. Список не делает N запросов за N карточками.
- Клиентская тренировка использует эквивалентный пакетный endpoint, который
  разрешает только media ID, сохранённые в неизменяемом snapshot назначения.
- Приватные S3-объекты не становятся публичными; URL остаются короткоживущими
  подписанными GET-ссылками.

## Архитектура

### Канонизация новой обложки

Редактор сразу рисует выбранный файл либо кадр видео в canvas с центральным
cover-crop 16:9. Canvas уменьшает изображение до 320×180 и кодирует WebP;
качество начинается с 0.60 и уменьшается до достижения 100 KiB. Это даёт
быстрый локальный предпросмотр и обычно передаёт в S3 уже малый файл.

Сервер остаётся источником гарантии. `thumbnail-uploads` принимает только
WebP до 100 KiB. После S3 `HEAD` подтверждает объект, API помещает его в
долговечную очередь нормализации. Отдельный `thumbnail-worker` скачивает
временный объект, проверяет, что это изображение, повторно делает центральный
crop 16:9, кодирует 320×180 WebP с ограничением 100 KiB и заменяет тот же
приватный объект только после успешного результата. MediaObject получает
статус `PROCESSING`, затем `READY` или `FAILED`; упражнение может ссылаться
лишь на `READY`.

Отдельная очередь необходима, чтобы API не выполнял CPU-затратное
перекодирование в запросе и чтобы сбой воркера был наблюдаемым и повторяемым.
Очередь и lease следуют существующему паттерну `ExerciseVideoStream`.

### Доставка списков

Новый trainer endpoint принимает набор media ID и возвращает только готовые
обложки, принадлежащие упражнениям текущего тренера, в виде `{ media_id,
read_url }`. Он дедуплицирует ID и отклоняет отсутствующие/чужие объекты.

Новый assignment endpoint действует аналогично, но проверяет каждый ID против
сохранённого snapshot конкретного назначения. Это не открывает доступ к
текущим медиа упражнения, которых не было в назначенной тренировке.

PWA заменяет циклы запросов по одному media ID на один batch-вызов. `img`
использует `decoding="async"`; видимые карточки имеют обычную приоритетную
загрузку, а карточки за пределами экрана — `loading="lazy"`. Макет сохраняет
зарезервированное пространство 16:9 и не прыгает во время загрузки.

### Совместимость

Существующие `thumbnail_url` и старые `thumbnail_media_id` не мигрируются и
отображаются текущим путём. Новая строгая политика применяется только при
создании/замене обложки через обновлённый UI/API. Старые workout snapshots не
переписываются.

## Ошибки и наблюдаемость

- API возвращает `PROCESSING` после подтверждения и `READY` только после
  завершения worker.
- Невалидное изображение, превышение лимита или ошибка кодирования переводят
  задачу в `FAILED` с безопасным кодом причины; исходный объект не выдаётся.
- Worker забирает задачи с lease и увеличивает счётчик попыток, поэтому после
  рестарта незавершённая работа не теряется.
- Логи фиксируют только media ID и код ошибки, без подписанных URL и S3
  реквизитов.

## Тестирование

- Unit-тесты canvas helper: размер, 16:9 crop, WebP и ограничение размера.
- HTTP/service-тесты: валидация политики upload, состояния очереди и запрет
  привязки неготовой обложки.
- Worker-тест: успешная публикация, сбой и безопасный повторный захват lease.
- Authorization-тесты для trainer и assignment batch endpoints.
- Angular-тесты: один batch вызов для дедуплицированных media ID, lazy/async
  image attributes и fallback для legacy URL.
- Регрессия OpenAPI, mypy, Ruff, frontend typecheck и focused tests.
