# Handoff: TopTrainers — приложение (PWA клиент + тренер)

## Overview
TopTrainers — платформа для персональных тренеров и их клиентов. Этот пакет описывает UI двух PWA-приложений на единой дизайн-системе «Стадион», тёмная тема **«Табло»**:

- **Клиент** (телефон): экран «Сегодня», плеер тренировки.
- **Тренер** (телефон + десктоп «режим силы»): очередь «Обработать», дашборд, конструктор программ.
- **Общий**: регистрация клиента/тренера (email/пароль + OAuth: Яндекс, Т-Банк, VK).

Метафора продукта: спортивное «табло» — данные-первыми, моноширинные счётчики, «Лента недели» (беговая дорожка), лаймовый «Заряд» как единственный акцент действия.

## About the Design Files
Файлы в этом пакете — **дизайн-референсы, свёрстанные в HTML**. Это прототипы, показывающие внешний вид и поведение, **а не продакшн-код для копирования**. Задача — **воссоздать эти экраны в целевом кодовом окружении** (React/Vue/Next, React Native, Flutter и т.п.), используя его существующие паттерны, компонентную библиотеку и токены. Если окружения ещё нет — выбрать подходящий фреймворк (для PWA рекомендуется React + Vite или Next.js) и реализовать дизайн там.

Оба приложения задуманы как **PWA** (устанавливаемые, офлайн-плеер тренировки, пуш-уведомления).

## Fidelity
**High-fidelity (hifi).** Финальные цвета, типографика, отступы и радиусы заданы точно (см. Design Tokens). Воссоздавать пиксель-в-пиксель средствами кодовой базы. Изображения/видео/аватары — **плейсхолдеры** (штриховка / диагональная заливка); заменить реальными ассетами.

## Interactions & Behavior
- **Регистрация:** переключатель роли меняет копирайт/дальнейший онбординг (клиент → привязка к тренеру по коду; тренер → шаг 2 профиля, отсюда «шаг 1/2»). OAuth-кнопки запускают соответствующий провайдер (Яндекс ID, Т-Банк ID, VK ID). Валидация email формата и пароля ≥8 символов; кнопка «глаз» — показать/скрыть пароль.
- **Плеер (M2):** степперы ±повт/±вес, «Подход выполнен» инкрементит подход и запускает таймер отдыха (круговой прогресс, вибро в конце); по завершении всех подходов → следующее упражнение (счётчик 3/6). Видеоотчёт — запись/загрузка, уходит тренеру в очередь.
- **Очередь тренера (M3):** свайп влево «отложить», вправо «ответить»; на десктопе (D1) те же действия кнопками.
- **Конструктор (D2):** drag-and-drop блоков (хэндл `⠿`), хоткеи N / D / `/`; недели копируются («копия ▾»); публикация из «черновика».
- **Анимации:** переходы фокуса/hover 150–200ms ease; таймер отдыха — линейная анимация обводки; лента недели/бары — без обязательной анимации.
- **Респонсив:** мобайл 390 — одноколоночный поток; десктоп ≥1280 — многоколоночные табло. Тренерский UI живёт и в телефоне (M3), и в десктопе (D1/D2).

## State Management
- `auth`: role (client|coach), email, password, provider, step (1|2), errors.
- `client/today`: weekRibbon[7] (done|missed|today|future), workoutOfDay, streak, widgets.
- `player`: exerciseIndex/total, setIndex/total, reps, weightKg, restSeconds/remaining, videoReport.
- `coach/today`: summary{revenue, renewals, churnRisk, activeClients, avgCompletion}, queue[] (type, client, payload), feed[].
- `builder`: program{name, weeks[]}, selectedWeek, selectedDay, blocks[]{tag, name, sets, reps, weight, rest, media}, draft/published.
- Данные: аутентификация (OAuth провайдеры + email), тренировки/программы, чат/очередь, платежи (продления), метрики — предполагают REST/GraphQL API; офлайн-кэш плеера тренировки для PWA.
